# 本地 AI 企业工程政策知识库完整方案

## 1. 文档目的

本文档用于为当前项目中的 AI 对话窗提供一套可落地的本地私有化升级方案，目标是在现有 `Vue 3 + Vite + Cesium/OpenLayers` 前端基础上，扩展出企业级政策知识库能力，满足以下需求：

- 本地离线私有化部署
- 自动联网检索、下载政策原文并入库
- 文档保持完整、不切碎、支持长上下文读取
- 类 Obsidian 双向链接、文件关联图谱
- Agent 智能体 + 本地文件工具（OpenClaw）
- 按范本自动复刻工程文件

本文档输出形态为标准 Markdown，可直接用于立项、评审、拆分研发任务和编制实施计划。

## 3. 建设目标

### 3.1 总体目标

建设一套部署在本地或内网服务器上的企业工程政策知识库系统，作为当前 AI 对话窗的后端能力中心，为规划、自然资源、测绘、巡检、用地、招投标、工程报批等场景提供政策问答、原文追溯、依据比对、资料归档、模板生成和工程文档复刻能力。

### 3.2 核心能力目标

1. 检索采集
支持定时联网检索国家、省、市、区县政策网站，自动下载政策原文、附件和元数据。

2. 原文入库
所有政策以“原文完整文档”为主存，不做破坏性切碎，保留来源、标题、发布日期、发文字号、正文、附件、PDF、HTML、图片、抓取时间和校验摘要。

3. 长上下文阅读
模型调用时优先读取整篇政策原文或整章内容，支持长上下文窗口模型，减少碎片检索导致的断章取义。

4. 知识关联
支持文档双向链接、引用关系、主题标签、部门归属、时效状态、废止替代关系和工程事项关系，形成 Obsidian 风格知识网络。

5. Agent 工具化
支持 Agent 调用本地文件工具、政策检索工具、文档抽取工具、模板生成工具和工程文件复制工具，完成复杂任务闭环。

6. 工程范本复刻
根据企业已有模板，一键生成项目目录、台账、报审材料、政策依据清单、实施方案初稿和交付物骨架。

## 4. 总体原则

### 4.1 私有化原则

- 核心数据、模型服务、文档仓、索引库均部署在本地或内网
- 默认不依赖公网 SaaS 托管
- 支持断网运行知识问答、文档生成、图谱浏览和工程复刻

### 4.2 联网采集与离线服务分离

“本地离线私有化部署”和“自动联网检索”并不冲突，建议采用双区模式：

- 采集区：有受控外网访问能力，仅负责抓取政策网站和下载原文
- 服务区：内网离线运行，仅消费已审核入库的数据

这样既满足自动更新，又满足日常问答和业务使用的离线安全要求。

### 4.3 原文优先原则

- 知识库主对象是“完整文档”
- 切片仅作为辅助索引，不作为最终依据
- 回答必须可回溯到原文位置和来源地址

### 4.4 可追溯原则

- 每次回答必须附带引用文档、版本、抓取时间、条款位置
- 每次模板生成必须记录依据来源和生成链路

## 5. 总体架构

## 5.1 架构分层

建议采用六层架构：

1. 前端工作台层
复用当前项目 AI 对话窗，并新增知识卡片、政策原文预览、图谱面板、工程模板面板、任务执行面板。

2. API 网关层
统一暴露对话、检索、入库、图谱、模板、Agent 任务和文件操作接口。

3. Agent 编排层
负责意图识别、任务拆解、工具调用、长文阅读策略、引用拼装和结果回写。

4. 知识服务层
负责全文检索、元数据检索、向量检索、图谱检索、文档解析、版本管理和引用定位。

5. 数据存储层
负责原文对象存储、Markdown 仓库、关系库、向量库、图数据库和检索索引。

6. 采集同步层
负责政策网站抓取、下载、解析、去重、审核和入库。

### 5.2 推荐组件

- 本地模型服务：`Ollama` 或 `vLLM`
- 长上下文模型：优先 `Qwen Long Context`、`DeepSeek` 系列长上下文模型，离线时选本地可部署版本
- API 服务：`FastAPI` 或 `NestJS`
- 任务调度：`Celery + Redis` 或 `Quartz/N8N`
- 全文检索：`Elasticsearch` 或 `OpenSearch`
- 向量检索：`Milvus`、`Qdrant` 或 `pgvector`
- 图数据库：`Neo4j`
- 关系数据库：`PostgreSQL`
- 对象存储：`MinIO`
- 文档仓：本地文件系统 + Git 版本仓
- 本地文件工具：`OpenClaw` 作为 Agent 工具适配器

## 6. 核心模块设计

### 6.1 政策采集中心

#### 功能

- 配置政策来源站点
- 定时搜索“自然资源/国土空间/测绘/巡检/土地/规划/报批”等关键词
- 自动下载正文和附件
- 识别失效、废止、替代和修订版本
- 生成入库待审任务

#### 采集来源建议

- 国务院及部委官网
- 自然资源部及各省自然资源厅
- 发改委、住建厅、生态环境厅等配套部门
- 市县政府公示站
- 标准规范下载站点

#### 入库流程

1. 定时任务触发检索
2. 命中页面抓取 HTML/PDF/附件
3. 解析标题、发文号、发布日期、部门、正文
4. 计算文件指纹去重
5. 生成标准 Markdown 和原文快照
6. 人工审核或规则审核
7. 正式入库并建立链接关系

### 6.2 原文文档仓

#### 存储原则

- 原始文件原样保存：`pdf/html/doc/docx/ofd/zip`
- 解析后形成标准 Markdown 副本
- 每份文档保留唯一 `doc_id`
- 同时保存：
  - 原始路径
  - 提取文本
  - 标题
  - 来源 URL
  - 发布机构
  - 发布时间
  - 时效状态
  - 版本号
  - 内容摘要
  - 引用锚点

#### 标准 Markdown 结构建议

```md
# 文档标题

## 元数据
- doc_id:
- 标题:
- 发布机构:
- 发文字号:
- 发布时间:
- 实施时间:
- 时效状态:
- 来源链接:
- 抓取时间:
- 文件摘要:
- 标签:

## 正文

原文完整内容

## 附件
- 附件1
- 附件2

## 关联
- 上位政策:
- 下位政策:
- 替代关系:
- 关联工程事项:
- 双向链接:
```

### 6.3 长上下文阅读引擎

#### 目标

避免把政策切成过碎片段后丢失语义，采用“整文优先 + 章节辅助 + 引文定位”的读取策略。

#### 读取策略

- 一级：整篇全文直接送入长上下文模型
- 二级：按一级标题、条款章节点切分，但保持章节完整
- 三级：仅在超长文档场景下做语义段落切分

#### 建议策略

- 20 万 token 内文档，优先整文读取
- 超长文档采用“目录定位 + 章节展开 + 精读段回填”
- 回答输出时强制附带条款出处

#### 检索模式

- 全文检索：适合明确法规名或条款关键词
- 元数据检索：适合按地区、年份、部门筛选
- 向量检索：适合模糊问题和场景问法
- 图谱检索：适合查上下位关系、替代关系、关联事项

### 6.4 双向链接与知识图谱

#### 双向链接对象

- 文档到条款
- 文档到工程事项

- 主题标签
- 工程事项
- 模板文件

#### 图谱关系类型

- `废止`
- `修订`
- `依据于`
- `适用于`
- `生成自`
- `附件属于`

#### 前端表现

- 文档详情页显示反向引用
- 对话结果中的依据条款可点击跳回原文
- 提供图谱视图显示相邻文档和关联工程事项
- 支持 Obsidian 风格 `[[双向链接]]` 与 `#标签`

### 6.5 Agent 智能体与 OpenClaw 工具层

#### Agent 角色建议

- 政策检索 Agent：查政策、找条款、判时效
- 原文校验 Agent：比对来源、检测缺页、定位引用
- 工程编制 Agent：根据模板生成目录与文件
- 项目归档 Agent：整理材料、归类命名、补元数据

#### OpenClaw 工具建议封装

- `list_files`
- `read_file`
- `write_file`
- `copy_template_tree`
- `render_markdown`
- `extract_pdf_text`
- `create_project_scaffold`
- `append_policy_references`

#### Agent 调用闭环

1. 用户发起任务
2. Agent 识别是问答、检索、比对还是生成
3. 调用检索工具找到原文
4. 调用长文阅读器提炼依据
5. 需要输出文件时调用 OpenClaw
6. 生成结果回显到对话窗并落盘

#### 输出

- 调查表
- 台账模板

- 静态模板复制：直接复制目录与空白文件

## 14. 验收标准

### 14.1 功能验收

- 能自动检索至少 5 类政策来源
- 能下载正文与附件并完整入库
- 能按标题、地区、部门、时间、关键词检索
- 能回答问题并给出原文依据
- 能查看双向链接和关系图谱
- 能调用 OpenClaw 在本地生成工程目录和模板文件
- 能按范本自动复刻至少 3 种项目模板

### 14.2 性能验收

- 常规问答首字返回时间小于 5 秒
- 原文打开时间小于 2 秒
- 10 万篇以内文档全文检索响应小于 3 秒

### 14.3 安全验收

- 内网断网后仍可完成问答和模板复刻
- 文件工具不能越权写目录
- 所有引用可回溯到原文

## 15. 风险与应对

### 风险 1：纯向量切片导致政策理解失真

应对：采用“整文优先，章节辅助”的长上下文策略。

### 风险 2：政策网站结构不统一，采集稳定性差

应对：建立站点适配器和人工审核缓冲区。

### 风险 3：本地模型上下文不足

应对：优先选长上下文模型，并增加章节级阅读编排。

### 风险 4：文件工具越权

应对：OpenClaw 仅开放白名单目录和模板目录。

## 16. 最终建议

对当前项目，最稳妥的落地路径不是直接把所有能力继续塞进 `SmartAnalysis.vue`，而是：

1. 保留当前 AI 对话窗作为统一入口
2. 新增本地知识库后端和 Agent 编排层
3. 以“完整政策原文仓 + 长上下文阅读 + 双向链接图谱 + OpenClaw 文件工具”作为核心能力底座
4. 逐步把问答、检索、归档、模板生成、工程复刻都汇聚到这个入口

这样既能延续你现在项目里的 AI 使用体验，也能把它真正升级为可在企业内网长期运行的工程政策知识平台。
